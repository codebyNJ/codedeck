01 · Research

Which GPUI, and what it can't do yet

Checked on crates.io, GitHub, and docs.rs on 21 Nov 2026. GPUI itself is still pre-1.0. The safest way in is the wrapper a shipping product already depends on.

Pick

gpui-kit

0.10.0 · Longbridge · 2026-11-16

Pins a matching GPUI snapshot and adds gpui-base, which is unstyled behavior: focus, text input, virtual list, popovers, motion. We turn off the styled components and own the whole look. It powers Longbridge Pro.

ships a real appdefault-features = falseexact pin

gpui

0.2.2 · Zed · 2026-10-30

Upstream. Built around Zed's needs, with breaking changes common. It's what gpui-kit wraps anyway, so it's our fallback.

fallbackbreaks often

gpui-ce

0.3.0 · community · 2026-10-20

A community fork for standalone apps, with its own cadence and RFCs. Promising, but young, with about 28k downloads.

watchyoung
No scale on divTransforms exist only on svg(). Jelly and wobble need size animation or a tiny custom element. Spike #1.
No spring easingEasing is any Fn(f32)→f32, so spring() is ours and about 5 lines. Overshoot works.
Film at 120 fpsThe pixel meadow is about 35k cells a frame. Paint one image per frame. Spike #2.
Mac chrome worksTransparent titlebar, traffic-light position, and blurred background are all supported.
02 · Layers

Dependencies only point down

The domain never sees the UI, and the design system never sees the domain. The app is the only place they meet.

codedeck
binary · the app
  • window, menus, actions, keymap
  • AppState entity
  • screens: onboarding, home, project, ⌘K, settings, license
→
codedeck_ui
lib · the design system
  • theme tokens light/dark, fonts
  • spring · squish · jelly
  • GelButton, Segmented, Pill, Badge, Card, EditorButton, Mascot
  • gallery example
→
gpui-kit
external · pinned
  • GPUI (rendering, layout, input, windows)
  • gpui-base (behavior only)
  • no styled components
codedeck also uses codedeck_core, plain Rust with no GPUI: scan, stack, git, agent sources, matcher, index, watch, launch, settings, license

06 · How data moves

  
Scan off the main thread, render on it

  
GPUI gives you a foreground executor (the UI thread) and a background one. Scanning never blocks a frame.

  

    
Main thread · GPUI

      
1Launch: AppState loads index.db and Home renders cached projects in under 200 ms

      
2AppState::rescan calls cx.spawn and hands the work to the background

      
5this.update(cx, |state, cx| state.apply(result); cx.notify())

      
6Views that observe AppState re-render, and new cards spring in

    
Background executor · codedeck_core

      
3scan::find_projects(roots), then stack and git for each root

      
4sources::read_all() (claude, opencode, codex), then matcher::assign, then index::save

      
↻watch (FSEvents) sees a new session file and starts again from step 2
